# DreamWeaver — Project Worklog

## Project Overview
DreamWeaver: a dream capture → AI (Gemini via z-ai-web-dev-sdk) structured analysis → longitudinal pattern memory → interactive Subconscious Arcade (RE-ENTER DREAM with REPLAY/REWRITE/CONFRONT) product.

Adapted from the master build instruction (which targeted Google Cloud Run + Firebase + Firestore + Secret Manager) to this sandbox stack:
- Firebase Auth → NextAuth.js v4 Credentials provider (bcrypt-hashed passwords in Prisma)
- Firestore → Prisma + SQLite, with server-side ownership enforcement on every API route
- Gemini API → z-ai-web-dev-sdk LLM skill (backend only), structured JSON output + zod validation
- Secret Manager → server-only SDK credentials (never shipped to client)
- Cloud Run → Next.js dev server on port 3000

## Design system
- Light mode primary. Palette: #F2F1EF (warm off-white), #B1A6A4 (mauve), #697184 (slate), #D8CFD0 (dusty rose), #413F3D (ink).
- Aesthetic: lucid + editorial + premium journal + soft surrealism + subtle scientific observatory. No neon cyberpunk.
- Serif display (Cormorant Garamond) for headings, Geist sans for body, JetBrains Mono for data labels.
- Dream-state-responsive atmospheric background (fear → muted/compressed; lucidity → brighter/expansive; stable → neutral; collapse → subtle distortion).
- Sticky footer at bottom of viewport.

## Architecture constraints (sandbox)
- Single `/` route (SPA with client-side view switching via Zustand + hash). All real logic under `/api/*`.
- API uses `requireUser()` server helper that throws 401 if not authenticated and verifies every record's `userId` matches the session user before read/write.
