## Unresolved issues / risks / next-phase recommendations
- True streaming depends on the upstream model server honouring `stream:true` + `text/event-stream`. If it ever returns parsed JSON instead, `generateArcadeTurnStreaming` falls back to a single delta emit (the whole scene text in one chunk) — UX is degraded but correctness is preserved. Worth re-verifying after SDK updates.
- Calendar popover is desktop-only (mouseenter doesn't fire on touch). Mobile keeps click-to-drill-down. A long-press handler could be added for mobile popover parity if desired.
- Streaming caret + text are decorative; on very slow networks the model could pause mid-stream. The elapsed-seconds timer remains visible so the user knows the turn is still in flight.
- The non-streaming `/turn` route is preserved as a fallback. If the streaming endpoint proves stable over multiple rounds, the non-streaming route could be deprecated. For now both exist.
- Turn latency is still ~7–8s for the streaming path (the model still has to produce the full JSON before the route can apply the authoritative delta). The streaming UX lets the user read instead of stare, but doesn't reduce total time. A two-call decomposition (scene text first, structured delta second) would reduce perceived latency further at the cost of doubling model calls — left for a future round.
- Dashboard prompt set could grow; consider sourcing prompts from the user's own motifs (e.g. "Tonight, watch for X — it has returned N times in your dreams") instead of a static rotation. That would require a small endpoint or pattern-aware client logic.
