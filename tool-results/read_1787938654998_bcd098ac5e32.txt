   461→## Unresolved issues / risks / next-phase recommendations
   462→- The r8 custom CSS rules initially didn't appear in the compiled stylesheet — Turbopack's CSS chunk caching didn't pick up edits to globals.css until a tsx file was also touched. Once utils.ts was edited, the next compile pulled in all the new rules. If r9+ adds more custom CSS, it should expect a one-request delay before the new rules show up; touching any tsx file forces the recompile. Not a bug — a Turbopack HMR characteristic.
   463→- The Atlas "Browse N dreams" stacked list fetches /api/dreams in addition to /api/patterns. react-query dedupes the request across views (journal, dashboard, atlas all use the same queryKey), but the Atlas view now has a hard dependency on /api/dreams being available. If /api/dreams is rate-limited in the future, the Atlas would need a graceful degradation path. Acceptable for now.
   464→- The TTS cache is in-memory only. If the dev server restarts (or in a multi-instance production deploy), the cache cold-starts. For a single-instance sandbox this is fine. For production, replacing the in-memory Map with a Redis or filesystem cache would persist across restarts. The cache key (text-hash + voice + speed) is portable.
   465→- The longitudinal insight priority order is hand-tuned. A future enhancement could let the user pin a specific insight kind (e.g. "always show lucidity trend, never fear trend") via a profile preference. Currently the strongest available signal wins automatically.
   466→- The Atlas co-occurrence panel uses the existing `recurringPairs` from patterns.ts (threshold: count >= 2). For users with many dreams, the panel could grow large. A "show more" expandable could be added if users have >8 pairs.
   467→- The capture-surface focus glow is on the wrapper, not the textarea itself — so the glow persists when the user moves focus to the speak button or the sample buttons inside the same wrapper. That's intentional (the whole card is "active"), but if it ever feels too aggressive, restricting to `textarea:focus-within` only is a one-line change.
